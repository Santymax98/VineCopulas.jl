# Cross-library correctness gate

This directory validates `VineCopulas.jl` against **R/rvinecopulib** before any
R-vine fitting timings are interpreted. `rvinecopulib` is the primary external
reference because the package's existing numerical/performance comparison is
already organized around the R interface to `vinecopulib`.

This is intentionally separate from `benchmarks/fitting/`: it is a correctness
gate, not a speed benchmark.

The gate has four layers:

1. **Fixed pair-copulas.** Shared parameters are evaluated for Independence,
   Gaussian, Student-t, Clayton, Gumbel, Frank, Joe, BB1, BB6, BB7 and BB8,
   including representative rotations. Per-observation log-density,
   h-functions and inverse h-functions are compared.
2. **Fixed general R-vines.** Both libraries receive the same R-vine structure,
   edge copulas and evaluation points. The suite includes a genuinely branching
   5D structure with rotated pair-copulas and the 7D structure fixture used by
   `vinecopulib`'s own structure tests. Log-density, Rosenblatt and inverse
   Rosenblatt results are compared directly.
3. **Fixed-structure fitting.** A single sample generated by `rvinecopulib` from
   the shared branching 5D specification is fitted by both engines while the
   structure is held fixed. Represented edges, selected family/rotation,
   parameters, parameter count and likelihood are compared.
4. **Automatic Dißmann/Kruskal selection.** The same sample is fitted without a
   structure using absolute Kendall-tau weights and deterministic Kruskal
   maximum-spanning trees. Edges are compared as conditioned/conditioning sets
   rather than raw matrix strings, so equivalent matrix encodings do not create
   false disagreements.

## Important h-function convention

The two libraries use different names for the same conditional quantities.
`VineCopulas.jl` uses

- `hfunc1(C,u,v) = F(U1 <= u | U2 = v)`;
- `hfunc2(C,u,v) = F(U2 <= v | U1 = u)`.

`rvinecopulib` numbers the h-function by the **conditioning variable**:
`cond_var = 1` means condition on the first variable and `cond_var = 2` means
condition on the second. The R reference script therefore translates the
outputs to the Julia naming convention before comparison. The same translation
is applied to inverse h-functions.

## Setup

From the package root, instantiate the Julia benchmark environment:

```bash
julia --project=benchmarks -e 'using Pkg; Pkg.develop(path="."); Pkg.instantiate()'
```

Install the R reference package if needed:

```bash
Rscript -e 'install.packages("rvinecopulib", repos="https://cloud.r-project.org")'
```

Shared numerical inputs are versioned under `fixtures/` so changing the harness does not change the statistical test sample. Julia prepares the bridge files and performs all comparisons; R is used only as the external `rvinecopulib` reference engine.

Record the environment with:

```bash
bash benchmarks/correctness/record_environment.sh
```

## First run: common model space

This aligns the primary model space in both statistical engines: Gaussian,
Student-t, Clayton, Gumbel, Frank and Joe; rotations enabled; independence
excluded; AIC; no family preselection; full truncation; absolute Kendall-tau
edge weights; and Kruskal maximum-spanning trees.

```bash
PARITY_N=800 PARITY_FIT_MODE=common \
  bash benchmarks/correctness/run_correctness_gate.sh
```

For the first diagnostic run:

```bash
PARITY_N=300 PARITY_FIT_MODE=common \
  bash benchmarks/correctness/run_correctness_gate.sh
```

## Second run: package-default model space

After `common` passes, exercise the broader current Julia search space:
independence plus BB1/BB6/BB7/BB8, using BIC.

```bash
PARITY_N=800 PARITY_FIT_MODE=default \
  bash benchmarks/correctness/run_correctness_gate.sh
```

Run both modes in one invocation with `PARITY_FIT_MODE=both`.

## Execution order

The runner is deliberately sequential:

```text
fixed pair-copulas
        ↓
fixed R-vines
        ↓
fixed-structure fitting
        ↓
automatic Dißmann/Kruskal selection
```

If the fixed-model stage fails, the script stops before fitting. This prevents a
primitive orientation/traversal discrepancy from being misdiagnosed as a model
selection difference.

## Outputs

Generated inputs and results live under `benchmarks/correctness/data/` and
`benchmarks/correctness/results/`; both are git-ignored. The two human-readable
reports are:

- `results/fixed_report.txt`
- `results/fit_report.txt`

A failure is diagnostic, not something to hide by loosening tolerances. Pair or
fixed-vine discrepancies must be resolved before interpreting fitting;
fitting/selection differences must be resolved or explicitly documented before
timing benchmarks are promoted to the public comparison page.

For fitting parity, the automatic selector uses the same finite candidate
parameter boxes as `vinecopulib` for families where the public `Copulas.jl`
domain is broader. These are selection-only bounds: direct construction and
direct family use in `Copulas.jl` remain unchanged. Keeping the model spaces
aligned prevents an optimizer-domain difference from being misdiagnosed as an
R-vine traversal error.

## Candidate-score diagnostics

The fitting gate also writes `results/fit_candidates_julia.csv` and
`results/fit_candidates_r.csv`.  For every automatically selected vine edge, each file records
the best rotation and fitted score for every base family in the active parity
family set.  These tables are diagnostic only: they do **not** relax or change
the PASS/FAIL criteria.  When the two engines select different families,
`fit_report.txt` prints the top candidate rankings and the winner-runner score
gap for each engine so near-ties can be distinguished from genuine fitting
discrepancies.
